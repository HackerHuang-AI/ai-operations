# ai-operations 项目定位

## 一、平台整体模块划分

平台按用户工作台、运营控制面、基础域、运行时引擎和治理分析域拆分。下表只说明职责，建设状态由各模块自己的定位文档维护。

| 模块 | 平台职责 |
| --- | --- |
| `ai-base` | 用户、个人空间、企业租户、组织及租户侧角色、菜单、权限基础域（非运营角色） |
| `ai-operations` | 独立运营身份与权限、平台初始化编排与运营配置 |
| `ai-admin-gateway` | 用户租户入口、认证、路由与追踪 |
| `ai-operations-gateway` | 无租户运营入口、认证、路由与追踪 |
| `ai-admin-web` | 用户 AI 工作台兼企业智能管理平台 |
| `ai-operations-web` | 运营控制台 |
| `ai-agent` | 多 LLM 平台协议适配 |
| `ai-mcp` | 内置工具与外部 MCP Server 接入 |
| `ai-orchestration` | Agent 任务编排与 ReAct 循环 |
| `ai-memory` | 会话上下文与长期记忆 |
| `ai-knowledge` | 知识库与 RAG |
| `ai-eval` | 模型、Agent 及其调用质量评测 |
| `ai-experiment` | 实验分流与版本对比 |
| `ai-analysis` | 传统规则扫描与 AI 代码分析 |

## 二、项目背景与定位

`ai-operations` 是平台运营控制面，面向平台运营人员。运营链路为 `ai-operations-web` → `ai-operations-gateway` → `ai-operations`，使用独立运营账号及 `ops` 会话，没有个人空间或企业租户登录上下文。

本模块负责运营身份与权限、平台初始化方案及执行编排、运营变量和跨模块能力规划。运营账号、角色、菜单和权限归本模块；用户、个人空间、企业租户、组织及用户侧角色菜单权限归 `ai-base`，两套身份和授权体系不混用。

模型、工具、知识库及用户 Agent 等资源仍归其业务模块。跨域运营通过领域服务契约完成，不直接写入其他模块的数据表。运营可以在明确授权范围管理租户对象，但目标租户是业务对象，不是运营人员的登录身份。

## 三、本模块功能定位

- 管理独立运营账号、登录身份、会话、运营角色、菜单与权限；
- 管理平台初始化计划、初始化项、执行批次和执行记录；
- 定义用户侧组织、菜单、角色等基础数据的初始化方案，并调用 `ai-base` 执行；
- 管理不属于 Nacos 技术配置的运营变量，例如平台默认策略、功能启用范围和初始化模板参数；
- 维护模块、能力和依赖关系的规划视图，为平台建设、发布和运营提供统一入口；
- 提供初始化状态、配置版本和变更审计的查询能力。

## 四、职责边界与模块协作

| 协作模块 | `ai-operations` 负责内容 | 对方模块负责内容 |
| --- | --- | --- |
| `ai-operations-web` | 运营接口、身份授权及操作规则 | 运营登录、初始化、规划和配置治理交互，不承担租户工作台 |
| `ai-operations-gateway` | 签发、查询和撤销无租户 `ops` 会话 | 运营请求认证、运营路由、限流与可信用户/会话头透传 |
| `ai-admin-gateway` | 用户侧入口和功能范围相关运营规划 | 租户用户请求认证、路由和可信租户上下文，不作为运营浏览器入口 |
| `ai-base` | 初始化方案、执行编排和记录，明确受控操作对象 | 用户、空间、企业组织及用户侧菜单、角色、权限的权威数据与领域校验 |
| `ai-agent` | 模型接入与可用范围的规划信息 | 模型凭证、协议适配、调用路由与运行时容错 |
| `ai-mcp` | 工具与 MCP Server 的接入规划信息 | 工具注册、连接管理、发现与执行 |
| `ai-orchestration` | Agent 能力组合与发布方案的规划信息 | Agent 运行流程、状态流转和工具调用编排；用户设计/发布资源的具体服务划分后续确定 |
| `ai-memory`、`ai-knowledge` | 资源初始化与运营策略的规划信息 | 会话、记忆、知识库、文档和检索数据的管理 |
| `ai-eval`、`ai-experiment`、`ai-analysis` | 评测、实验和分析任务的运营规划信息 | 任务执行、数据采集、分析和结果产出 |

个人 Agent 默认私有，平台数据库存储不赋予运营人员默认读取权。企业市场内容由用户主动发布，只由发布者更新并具有版本管理；运营治理不等于代替发布者编辑，也不允许连带获取凭据、个人记忆或无权共享的知识。下载与维护细节后续设计。

用户工作台兼具企业智能管理定位，企业/工作台任务下发及司库等业务系统接入是后续方向；本模块提供必要的运营协同，不承接用户工作台的具体业务执行。

## 五、能力建设规划

| 阶段 | 建设内容 | 预期产出 |
| --- | --- | --- |
| 运营身份与权限闭环 | 运营用户、角色、菜单、权限和会话管理 | 独立于租户的运营访问控制与审计 |
| 初始化建模 | 初始化计划、初始化项、模板参数、执行批次和执行记录 | 可版本化、可追溯的初始化方案与数据模型 |
| 基础域初始化 | 通过 `ai-base` 服务契约执行用户侧组织、菜单、角色和权限初始化 | 幂等执行、失败重试、结果查询与审计 |
| 运营变量 | 平台默认策略、功能范围和模块能力规划的管理与发布 | 受版本控制的运营变量及变更记录 |
| 跨模块运营协同 | 模块能力目录、依赖关系、资源初始化状态与统一运营视图 | 面向发布和运营的跨模块规划视图 |

## 六、能力建设状态

| 能力 | 当前建设状态 | 现状说明 |
| --- | --- | --- |
| 工程与通用治理 | **已具备** | 四层 Maven 骨架、Nacos、Dubbo、国际化、线程池、OkHttp 与重试基础能力已具备。 |
| 运营身份与会话 | **部分具备** | 已有独立运营用户/身份/登录审计数据及登录、短信验证码、会话查询和退出实现，签发 `ops` 会话，不包含租户身份。生产短信与 SSO 待完善。 |
| 运营角色、菜单与权限 | **部分具备** | 运营角色和菜单等数据模型已具备，面向运营前端的完整查询、管理及授权闭环待建设。 |
| 初始化计划与执行记录 | **待建设** | 初始化计划、初始化项、执行批次、执行记录的数据模型和服务尚未实现。 |
| 基础域初始化协同 | **待建设** | 尚未接入 `ai-base` 的组织、菜单、角色和权限领域服务。 |
| 运营变量管理 | **待建设** | 运营变量的定义、版本、发布和审计尚未实现。 |
| 跨模块规划视图 | **待建设** | 模块能力目录、依赖关系和资源初始化状态尚未建设。 |

## 七、主要技术栈

| 功能 | 关键技术栈 |
| --- | --- |
| 运营账号及计划、变量、执行记录 | MySQL、MyBatis-Plus |
| 运营会话 | Redis Opaque Session、独立身份认证策略 |
| 跨模块初始化协同 | Dubbo Triple、Facade 契约 |
| 运营配置与动态治理 | Nacos、版本化配置、变更审计 |
| 任务执行可靠性 | 线程池、指数退避重试、TraceId |
