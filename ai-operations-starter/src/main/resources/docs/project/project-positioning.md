# ai-operations 项目定位

## 一、平台整体模块划分

平台按基础域、运行时引擎、运营控制面和治理分析域拆分：

| 模块 | 平台职责 | 当前建设状态 |
| --- | --- | --- |
| `ai-base` | 用户、租户、组织、权限与菜单基础域 | 数据模型、迁移脚本、实体与 Mapper 已具备；业务服务和 SSO 待建设 |
| `ai-operations` | 平台规划、初始化编排与运营配置管理 | 工程基础骨架已具备；规划、初始化数据与运营配置待建设 |
| `ai-gateway` | 统一流量入口、认证、路由与追踪 | TraceId、访问日志、JWT 过滤器已实现；路由和 SSO 治理待完善 |
| `ai-agent` | 多 LLM 平台协议适配 | 多平台文本、流式、多模态和 Function Calling 已具备 |
| `ai-mcp` | 内置工具与外部 MCP Server 接入 | 工具路由、MCP Client、SSE/STDIO 接入已具备 |
| `ai-orchestration` | Agent 任务编排与 ReAct 循环 | DTO、Facade 和技术底座已具备；核心编排未实现 |
| `ai-memory` | 会话上下文与长期记忆 | DTO、Facade 和技术底座已具备；存储与检索未实现 |
| `ai-knowledge` | 知识库与 RAG | 知识库、文档、解析、向量化、Milvus/MinIO 接入已具备 |
| `ai-eval` | 模型、Agent 及其调用质量评测 | DTO、Facade 和技术底座已具备；评测执行未实现 |
| `ai-experiment` | 实验分流与版本对比 | DTO、Facade 和技术底座已具备；分流与分析未实现 |
| `ai-analysis` | 传统规则扫描与 AI 代码分析 | 多代码平台适配、PR 分析及多阶段部署编排已具备 |

## 二、项目背景与定位

平台需要以可追溯、可重复的方式完成系统初始化，并持续维护跨模块的运营规划与配置。`ai-operations` 是平台运营控制面：负责定义初始化方案、编排初始化执行、管理平台运营变量和记录执行结果；它不承载各业务域资源的最终数据。

组织、菜单、角色和权限的权威数据仍归属 `ai-base`；模型、工具、知识库等运行时资源仍分别归属其领域模块。`ai-operations` 只保存初始化计划、变量和执行记录，并通过领域模块的服务契约完成受控初始化，避免绕过领域边界直接写入其他模块的数据表。

## 三、本模块功能定位

- 管理平台初始化计划、初始化项、执行批次和执行记录；
- 定义组织、菜单、角色等基础数据的初始化方案，并调用 `ai-base` 执行；
- 管理不属于 Nacos 技术配置的运营变量，例如平台默认策略、功能启用范围和初始化模板参数；
- 维护模块、能力和依赖关系的规划视图，为平台建设、发布和运营提供统一入口；
- 提供初始化状态、配置版本和变更审计的查询能力。

## 四、职责边界与模块协作

| 协作模块 | `ai-operations` 负责内容 | 对方模块负责内容 |
| --- | --- | --- |
| `ai-base` | 初始化方案、执行编排和记录 | 用户、租户、组织、菜单、角色、权限的权威数据及领域校验 |
| `ai-gateway` | 平台入口、功能范围等运营策略的规划 | 路由、认证、限流和请求链路的实际执行 |
| `ai-agent` | 模型接入与可用范围的规划信息 | 模型凭证、协议适配、调用路由与运行时容错 |
| `ai-mcp` | 工具与 MCP Server 的接入规划信息 | 工具注册、连接管理、发现与执行 |
| `ai-orchestration` | Agent 能力组合与发布方案的规划信息 | Agent 运行流程、状态流转和工具调用编排 |
| `ai-memory`、`ai-knowledge` | 资源初始化与运营策略的规划信息 | 会话、记忆、知识库、文档和检索数据的管理 |
| `ai-eval`、`ai-experiment`、`ai-analysis` | 评测、实验和分析任务的运营规划信息 | 任务执行、数据采集、分析和结果产出 |

## 五、能力建设规划

| 阶段 | 建设内容 | 预期产出 |
| --- | --- | --- |
| 第一阶段：初始化建模 | 初始化计划、初始化项、模板参数、执行批次和执行记录 | 可版本化、可追溯的初始化方案与数据模型 |
| 第二阶段：基础域初始化 | 通过 `ai-base` 服务契约执行组织、菜单、角色和权限初始化 | 幂等执行、失败重试、结果查询与审计 |
| 第三阶段：运营变量 | 平台默认策略、功能范围和模块能力规划的管理与发布 | 受版本控制的运营变量及变更记录 |
| 第四阶段：跨模块运营协同 | 模块能力目录、依赖关系、资源初始化状态与统一运营视图 | 面向发布和运营的跨模块规划视图 |

## 六、能力建设状态

| 能力 | 当前建设状态 | 现状说明 |
| --- | --- | --- |
| 工程与通用治理 | **已具备** | 四层 Maven 骨架、Nacos、Dubbo、国际化、线程池、OkHttp 与重试基础能力已具备。 |
| 初始化计划与执行记录 | **待建设** | 初始化计划、初始化项、执行批次、执行记录的数据模型和服务尚未实现。 |
| 基础域初始化协同 | **待建设** | 尚未接入 `ai-base` 的组织、菜单、角色和权限领域服务。 |
| 运营变量管理 | **待建设** | 运营变量的定义、版本、发布和审计尚未实现。 |
| 跨模块规划视图 | **待建设** | 模块能力目录、依赖关系和资源初始化状态尚未建设。 |

## 七、主要技术栈

| 功能 | 关键技术栈 |
| --- | --- |
| 计划、变量与执行记录 | MySQL、MyBatis-Plus |
| 跨模块初始化协同 | Dubbo Triple、Facade 契约 |
| 运营配置与动态治理 | Nacos、版本化配置、变更审计 |
| 任务执行可靠性 | 线程池、指数退避重试、TraceId |
